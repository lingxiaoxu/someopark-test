# Portfolio Risk Control — 独立研究与设计

日期：2026-09-17。状态：**PLAN ONLY**。本目录本次只新增 Markdown；没有实现、启动或部署风险服务，没有修改策略、前后端、交易、模型权重、调度器或 ontology 文档。

## 1. 要做什么

为 MRPT、MTFS、SSRS、AISS、AEUS、BDC 六个权益策略建立独立的组合风险分析层。每天自动回答：

1. 官方组合到底赚亏多少，损益能够解释到什么程度？
2. 当前股份承担了哪些共同因子、行业、证券和尾部风险？
3. 若行情、相关性、流动性、借券和融资同时恶化，会损失多少、是否有现金承受？
4. 哪些风险已超过**人事先批准**的预算，哪些因数据不足还不能判断？
5. 不改策略信号的前提下，哪些降险方案成本较低、保留了更多原策略结构？

**自动计算、自动归因、自动生成有证据的分析；本期不自动调仓。** 风险分析与执行隔离。降低回撤和保留上涨敞口存在代价，系统要展示取舍，不能承诺“只避亏、不损盈利”。

## 2. 用户指定的数据合同

- 资本、收益、历史组合路径：只以 `someo-park-investment-management/public/data/strategy_performance.json` 和 `master_portfolio_performance.json` 为本模块权威。
- 实际持股数量：以 **QC 对应账户/部署的已执行持仓**为权威；NAV 股份是需要逐票核对的展示投影，不是 QC 回报。历史实际股份优先使用 QC 存档及经锚点核验的成交重建。
- NAV 和 exporter 目标仍完整保留，分别解释策略归属、冻结换算、舍入与尚未执行的下一版目标；不能把盘后目标提前算成当日 QC 实仓。
- 策略内部 $1m 账户可用于查明股数或损益桥，**不可充当本模块收益率、风险或限额的资本分母**。
- `master_equity` 才是六策略总资本。两个文件里的 `combined_equity` 含义不同，均不可直接替代六策略 Master。
- 官方业绩、QC 实际股份、NAV 展示/目标股份和券商购买力是不同对象。实际风险使用 QC 股数，资本分母仍使用上述两份 JSON；QC equity/cash 仅用于账户资金及净值桥核验。
- 接受官方历史序列作为分析输入；不因其生成方式重定义收益。历史证据不足只限制能做的归因和当时可知分析，不删除官方结果。

## 4. 与 ontology 的关系

已阅读根目录下的 [ONTOLOGY_CONTROL_PLANE_PLAN.md](../.claude/plan/systemic-strategies-plan/ONTOLOGY_CONTROL_PLANE_PLAN.md)。它当前也是规划，统一 `ontology/` 查询和治理接口尚未实现。

本模块定位为**本体之上的确定性风险计算与证据生产者**：

```text
现有业务文件与身份 registry（只读）
                 ↓
有版本、时间和来源的数据快照
                 ↓
确定性风险引擎 → 指标、归因、情景、约束、数据缺口
                 ↓
规则检查 → 可选 AI 解释/调查 → 人审阅的分析与提议
                 ↓
将来由 ontology 只读索引 Evidence / PipelineRun / GovDecision
```

复用现有 SPID、ISIN 和域内键；不建第二套证券主数据，不往原 registry 注册新对象。统一接口未完成期间，显式使用本地文件适配器；未来切换须通过同快照一致性验收，不做静默来源切换。

本期不改 `RiskManager.py`，不接管 SPAC 配资，不更新聊天 prompt/MCP 工具池，不影响 coding 的 `toPrompt` 或 morph 路径。Crypto W7/W8/W9/W10、macro、soccer、世界杯不进入这份六策略 Master 的资本和收益汇总；未来扩域须另建环境与资本合同。

## 5. 重新审视后的设计重点

- **五因子不是完整风控**：FF5 用于标准风格解释；行业拥挤、单票跳空、配对失效、清算和融资另做。
- **三个视角并列**：官方历史损益、QC 当前实仓的前瞻损失、账户的清算/融资能力。QC 执行损益另作官方损益的对照，不冒称二者天然一致。
- **不用单一最优模型裁决**：展示稳定/快速/压力模型的差异、估计误差和未知项，不挑风险最小的结果。
- **风险预算先有授权**：之前单票 5%、行业 25%、AISS 减半等仅研究例子，不能悄悄成为生效规则。
- **AI 不是计算器或交易授权人**：先做好可信事实，再让模型解释、检索证据、发现待调查问题。模型由用户后续选择。
- **按本项目尺度实施**：单机批处理、文件快照和可重建 DuckDB 即可起步；不建设机构级分布式交易控制平台。
