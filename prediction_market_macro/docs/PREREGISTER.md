## 登记格式

每条必须有:

| 字段 | 含义 |
|---|---|
| 登记日 | 写下判据的那天(不是想到的那天) |
| 改动 | 一句话,精确到函数/常数 |
| 事前假设 | 你认为它会改善**什么**,方向如何 |
| 判据 | 一个可以判"没成立"的数字 + 观察窗口 |
| K | 这是第几次在同一份数据上做检验(多重比较计数) |
| 结论 | 到期后填。**不许改判据** |

## 纪律五条(§25.1)

1. **75 天窗口是发现用的,不是判决用的。** 在它上面得到的任何数字都是线索;判决必须来自
   登记后的前向窗口。
2. **三等分持出是下限不是上限。** 一个改动如果只在某一段成立,它就是没成立。
3. **多重比较要计数。** 每试一个变体,K 加一;报告时必须带 K,不许只报最好的那个。
4. **不许动展示段。** 展示的回测段已冻结;任何新测量都不重 freeze,直到判据被明确回答。
5. **不许回溯应用。** 今天新加的门不许倒回去"如果当时有这个门会怎样"然后当作业绩。
   那是回测,不是记录。

必须挑明的三点读法:

1. **两条臂是嵌套的,不是互斥的。** `argmax_candidate` 先选、`defers_to_market` 后判,
   所以关掉过滤器不会改变买哪个结构,只会改变买不买。ON = `placed`,
   OFF = `placed + deferred`,OFF 是 ON 的超集。`n_forward` 数的是 OFF 臂,
   因为那才是规则作用的总体,也是唯一让两条臂都非空的口径 —— 这个口径写在代码里,
   不是事后挑的。

2. **两条臂都是"持有到结算"的反事实,ON 臂不是账本的真实 PnL。** 这一条是 2026-08-06
   发现并更正的:`_place_argmax` 只在 `fair <= cost`(即 net_edge ≤ 0)时下单,而
   `ops/exits` 在 `hold_edge < -0.06` 时平仓,所以 argmax 腿只能活在 [-0.06, 0]
   这条 6 分钱的窄带里。已有的 4 笔里 3 笔当轮开当轮平,-9.2%,根本没走到结算(#148)。
   本登记**故意**把退出策略在两臂间固定为"持有到结算",因为要孤立**入场**规则就只能
   固定退出;固定在哪里是个选择,这里事先写死。代价必须跟结论一起读:
   PR-2 的 ROI 不是 argmax 流的真实盈亏,判决只针对过滤器本身。

3. **"规则没用"是一个真结论,不是没找到东西。** 事前假设为空,所以 REMOVE 和 KEEP
   对称可信。但 REMOVE 也只是判决,评分器不会自己去改 `_place_argmax`。

**为什么现在是 0 而不是坏了:** 记录器 2026-08-06 才装上,而 argmax 流本身极稀疏 ——
全历史只有 4 笔 placed 腿,全部落在同一个事件(KXWTIW 2026-08-07)上,且 `shadow_argmax`
以 `(series, period)` 为主键,同一事件重复触发只算一次机会。deferred 臂的到达率此前从未
被记录,所以未知。按 placed 侧观察到的密度,20 笔是**以月计**的等待,不是以周计的。
下次复核时如果 `shadow_argmax` 仍然是 0 行,那才需要怀疑记录器本身。

⚠️ **#148 不得在 PR-2 到期前修。** 修 `_place_argmax` 就是在半途改掉本登记正在测的那个
旋钮,那正是 §25.1 存在的意义。顺序是:PR-2 走完 → 取判决 → 再动 #148。

**登记期内对 `ops/decide_all.py` 的一次改动(2026-08-06,#149):** `_has_any_open` ——

### PR-7 止损 / 止盈(#140 §25.5 持仓路径的后继)

**登记日 2026-08-05,写在 #142 那次 75 天重跑还在跑、我还没看到任何结果的时候。**
这一条分两步登记,因为**第二步该不该做,取决于第一步的答案**;先把第一步的判据写死,

#### 步骤 0 —— 鞅检验(诊断,不是策略,K=0)

这一步不产生任何交易规则,所以不计 K。它回答一个前置问题:**在这个 book 上,
任何基于价格的止损/止盈在原理上有没有可能是 +EV 的。**

二元合约的最大亏损本来就被 100% 本金封顶,所以止损**不能**"控制风险" —— 风险已经有界。
止损唯一可能的收益来源是:**跌下去之后还会继续跌**(市场对坏消息反应不足),
也就是价格**不是**结算结果的鞅。如果它是鞅,那么在任何价位平仓的期望值都等于持有到结算,
而你还要多付一次买卖价差 + 手续费 —— 止损就是纯亏。止盈同理,方向相反。

| | |
|---|---|
| 数据 | `walkforward` 的 `held_paths`(§25.5),75 天窗口,hybrid 流 |
| 构造 | 每条路径每天的结构中价净借记 `m_t`。对 bucket YES(>lo)+NO(>hi),
  `cost@mid = mid_lo + (1−mid_hi) − 1 = mid_lo − mid_hi` = **市场隐含的该结构付 $1 的概率**,
  所以 `m_t` 直接可以和结算结果 `y ∈ {0,1}` 比。单腿同理 |
| 检验 | (a) 全样本 `E[y − m_t] = 0`?(b) **回撤态** `m_t ≤ m_0 − 0.10` 的子样本上
  `E[y − m_t] < 0`?(c) **盈利态** `m_t ≥ m_0 + 0.10` 的子样本上 `E[y − m_t] > 0`? |

#### PR-13 补记 A(2026-08-28,与登记同日):前向计分器落地,并把"ladder"这个词钉死

登记当天就写计分器,理由是 #195 立下的那条:**登记了却没写计分器的假设,等于一条悄悄永远不会成熟的登记**,而 PR-13 的全部证据就是那个前向窗。计分器是 `research/shadow_otm.py`,由 `research/prereg.py` 的 `REGS` 每周调用(`ops/refresh.py:267` 的 `weekly_prereg_shadows`),判据、区间、腿数、α 全部只从模块常量读,**没有任何一个可以为了让结果通过而改动**。

写计分器时发现登记正文里"**ladder 腿**"这四个字有歧义,必须当场钉死,否则前向窗测的会是另一条假设:

| 口径 | 判据来源 | 能否在 T−1h 执行 | 发现期结果 |
|---|---|---|---|
| 发现脚本 `otm_sell.py::classify` | `恰好一条 YES` 且 `mid 之和 < 1.5` | **否**——它读结算 | 64 事件 / 156 腿 / **+0.0526** |
| `REGISTRY[s].structure == "ladder"` | 序列级标签 | 是 | 78 事件 / 255 腿 / **+0.0253** |
| **采用:`event_structure`(逐事件读 `strike_type`)** | 全部腿都是 `greater` / `greater_or_equal` | **是**——合约定义,挂牌即确定 | 64 事件 / 156 腿 / **+0.0526** |

- **发现期那张表是在"累积阶梯"口径下算的**:每条腿是 `print > K_i`,YES 腿互相嵌套,YES 个数就是印刷值的名次。`KXNATGASW` 40 条腿 21 条 YES 就是这个形状。
- **`REGISTRY.structure` 用同一个词涵盖了 `KXWTIW`**,而 KXWTIW 的腿是 13 条 `between` + 1 条 `less` + 1 条 `greater` 的**互斥分档**——最多一条能结 YES,于是每条腿天生就便宜,区间内 YES 率是被分档结构钉死的,不是任何 longshot 偏差。它 99 条区间内腿的实测是 **−0.018/腿**,方向相反。用它当前向口径会把发现期均值从 +0.0526 拉到 +0.0253,**那是在测另一条假设**。
